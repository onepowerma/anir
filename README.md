# أنير — مساعد واتساب لمتجر onepower.ma

أنير يرد على عملاء واتساب باسم المتجر: يجيب عن المنتجات وطريقة استعمالها (من بيانات الشركة المصنّعة والهيئات العلمية المعترف بها فقط)، يتعرف على المنتج من الصورة، يعطي سعر التوصيل، ويسجّل الطلب في ووكومرس بعد تأكيد العميل. وإذا طلب العميل موظفاً أو غضب أو سأل خارج معلوماته، يعطيه رابط واتساب رقم المحل ويرسل للفريق تنبيهاً بملخص المحادثة.

لا يحتاج المشروع إلى أي مكتبات: ملف `server.js` واحد يعمل على Node 20 أو أحدث.

## محتويات المجلد

| الملف | وظيفته |
|---|---|
| `server.js` | الخادم كله (واتساب، Claude، ووكومرس، الطلبات، التحويل لموظف) |
| `anir-prompt.md` | شخصية أنير وقواعده (لغة، سلامة صحية، مسار الطلب). يمكنك تعديل النص |
| `config.json` | بيانات المتجر: رقم الموظفين، أسعار التوصيل، طرق الدفع، ملاحظات السياسات |
| `knowledge/` | ملخصات موثّقة من مصادر علمية يستند إليها أنير (اختياري لكن مهم) |
| `.env.example` | قائمة المفاتيح السرية المطلوبة |
| `test/smoke.js` | اختبار تلقائي يحاكي واتساب وووكومرس وClaude |

## ما تحتاجه قبل البدء

1. حساب Meta Business (لديك) مع تطبيق واتساب Cloud API.
2. مفتاح Claude API من console.anthropic.com. هذا حساب منفصل عن اشتراك Claude العادي، ويُحاسَب حسب الاستعمال.
3. مفاتيح WooCommerce REST API من متجرك.
4. حساب على GitHub، وخدمة استضافة (شرح Render أدناه).

## الخطوة 1: مفاتيح ووكومرس

في لوحة WordPress: WooCommerce ← الإعدادات ← متقدم ← REST API ← إضافة مفتاح. اختر صلاحية قراءة/كتابة (Read/Write). انسخ `Consumer key` و`Consumer secret` فوراً لأنهما لا يظهران مرة ثانية.

## الخطوة 2: مفتاح Claude

من console.anthropic.com أنشئ API key، وأضف رصيداً في صفحة الفوترة. ضع حداً شهرياً للإنفاق من نفس الصفحة.

## الخطوة 3: واتساب (Meta)

أسماء القوائم عند Meta تتغير أحياناً، لكن الخطوات واحدة:

1. في developers.facebook.com أنشئ تطبيقاً من نوع Business وأضف منتج WhatsApp.
2. أضف رقم أنير. إذا كان الرقم مسجلاً في تطبيق واتساب أو واتساب بزنس على هاتفك فعليك حذف الحساب منه أولاً، وبعدها يعمل الرقم مع البوت فقط ولا يفتح على الهاتف. رقم الموظفين الثاني يبقى كما هو على الهاتف.
3. أنشئ رمزاً دائماً: في Business Settings ← Users ← System users، أنشئ مستخدماً، أعطه صلاحية على التطبيق وحساب واتساب، وولّد token بصلاحيتي `whatsapp_business_messaging` و`whatsapp_business_management`. هذا هو `WHATSAPP_TOKEN` (الرمز المؤقت الذي يظهر في صفحة البداية ينتهي خلال ساعات فلا تستعمله).
4. من صفحة WhatsApp ← API Setup انسخ `Phone number ID`.
5. من App settings ← Basic انسخ `App secret` وضعه في `META_APP_SECRET`.
6. أضف وسيلة دفع في حساب واتساب بزنس حتى تعمل المحادثات بعد الفترة التجريبية.

## الخطوة 4: عبّئ `config.json`

- `store.handoff_whatsapp`: رقم المحل (للموظفين) بالصيغة الدولية بدون + وبدون مسافات، مثل `212612345678`. الخادم لا يشتغل قبل ملئه.
- `store.staff_notify_numbers`: أرقام الموظفين التي تصلها تنبيهات واتساب (انظر ملاحظة التنبيهات أدناه).
- `store.notes`: أي معلومات تريد أن يعرفها أنير: ساعات العمل، سياسة الإرجاع والاستبدال، العروض. ما لم تكتبه سيحوّله أنير لموظف ولن يخمّنه.
- `shipping`: أسعار التوصيل حسب المدينة. غيّر `configured` إلى `true` بعد ملئها، وإلا يحوّل أنير كل أسئلة التوصيل لموظف. `free_over` هو حد التوصيل المجاني (اتركه `null` إن لم يوجد). مدينة غير مذكورة تأخذ `default_zone`.
- `payments`: الدفع عند الاستلام مفعّل مبدئياً. التحويل البنكي معطّل حتى تكتب بيانات الحساب في `instructions` وتجعل `enabled` يساوي `true`.

أبقِ مستودع GitHub **خاصاً** لأن `config.json` قد يحوي بيانات حسابك البنكي.

## الخطوة 5: النشر على Render

1. أنشئ مستودعاً خاصاً على GitHub وارفع إليه كل ملفات هذا المجلد (زر Add file ← Upload files). لا ترفع ملف `.env`.
2. في render.com اختر New ← Web Service واربط المستودع.
3. اضبط: Runtime = Node، Build Command فارغ، Start Command = `node server.js`.
4. اختر نوع خدمة مدفوعاً (تعمل دائماً). الخطة المجانية تنام عند الخمول فتتأخر الردود أو تضيع. تحقق من الأسعار الحالية في الموقع.
5. من Environment أضف كل المتغيرات الموجودة في `.env.example` بقيمها.
6. بعد النشر يعطيك Render رابطاً مثل `https://anir-xxxx.onrender.com`. افتحه، فإذا ظهر «Anir is running ✅» فالخادم يعمل.
7. لحفظ سجل المحادثات عند إعادة النشر أضف Disk وضع `DATA_DIR=/data`. هذا اختياري؛ بدونه يبدأ العملاء الحاليون محادثة جديدة بعد كل نشر.

يمكنك استعمال Railway أو أي VPS بنفس الطريقة، المهم أمر التشغيل `node server.js`.

## الخطوة 6: ربط Webhook بواتساب

في تطبيق Meta ← WhatsApp ← Configuration:

- Callback URL: `https://رابط-الخدمة/webhook`
- Verify token: نفس قيمة `WHATSAPP_VERIFY_TOKEN`
- بعد نجاح التحقق اضغط Manage واشترك في الحقل `messages`.

## الخطوة 7: التجربة

من هاتف آخر أرسل لرقم أنير: «عندكم كولاجين؟»، ثم صورة منتج، ثم ابدأ طلباً تجريبياً وتأكد أنه ظهر في WooCommerce ← الطلبات. جرّب أيضاً «بغيت نهضر مع موظف» وتأكد أن الرابط والتنبيه وصلا.

## تنبيهات الموظفين

تنبيه واتساب للموظفين لا يصل إلا إذا كان الموظف قد راسل رقم أنير خلال آخر 24 ساعة (قاعدة واتساب للرسائل غير القالبية). لذلك الأفضل تفعيل تنبيه تيليجرام المجاني:

1. في تيليجرام افتح `@BotFather` وأنشئ بوتاً، وانسخ الـ token إلى `TELEGRAM_BOT_TOKEN`.
2. أنشئ مجموعة للموظفين وأضف البوت إليها، وأرسل رسالة في المجموعة.
3. افتح `https://api.telegram.org/bot<TOKEN>/getUpdates` وانسخ قيمة `chat.id` (تكون سالبة للمجموعات) إلى `TELEGRAM_CHAT_ID`.

تصل التنبيهات بالمعلومات التالية: اسم العميل ورقمه ورابط فتح محادثته وسبب التحويل وملخص وآخر الرسائل. وتصل أيضاً إشعارات الطلبات الجديدة.

## قاعدة المعرفة العلمية

أنير مطلوب منه ألا يعتمد إلا على الشركات المصنّعة والأبحاث المعترف بها. أقوى طريقة لضمان ذلك أن تضع في مجلد `knowledge/` ملخصات قصيرة من المصادر الرسمية (NIH Office of Dietary Supplements وEFSA وغيرها) مع رابط كل مصدر، بالشكل الموجود في `knowledge/_template.md`. يبحث أنير فيها أولاً ويذكر المصدر، وإذا لم يجد شيئاً يعترف بذلك بدل أن يخمّن. ابدأ بالمواضيع الأكثر سؤالاً: الكولاجين، فيتامين C، الحديد، المغنيسيوم، أوميغا 3.

## مراجعة أوصاف المنتجات

أنير ينقل معلومات المنتج من صفحاتك في المتجر. أوصاف تحتوي ادعاءات علاجية مبالغاً فيها (مثل «يعالج…») لن يكررها، لكن الأفضل مراجعتها في الموقع نفسه لتتوافق مع ما يُسمح بقوله عن المكملات الغذائية.

## الاختبار الآلي

على جهاز فيه Node 20+: `node test/smoke.js`. يشغّل الخادم أمام خوادم وهمية ويتحقق من: التحقق من Webhook، رفض التوقيع الخاطئ، البحث في الكتالوج، قراءة الصور، إنشاء الطلب بسعر التوصيل الصحيح، والتحويل لموظف. هذا اختبار للمنطق ولا يغني عن التجربة الحقيقية في الخطوة 7.

## استكشاف الأخطاء

| العَرَض | الحل المحتمل |
|---|---|
| فشل التحقق من Webhook | `WHATSAPP_VERIFY_TOKEN` غير مطابق، أو الخادم لا يعمل |
| الرسائل تصل ولا يوجد رد | راجع Logs في Render. اضغط Subscribe على الحقل `messages` |
| `bad signature` في الـ logs | `META_APP_SECRET` خاطئ |
| لا يجد منتجات | مفاتيح ووكومرس لا تملك صلاحية Read، أو `WC_URL` خاطئ |
| يتوقف الرد بعد أيام | رمز واتساب المؤقت انتهى؛ استعمل رمز System User الدائم |
| خطأ في إصدار Graph | غيّر `GRAPH_VERSION` إلى إصدار أحدث من وثائق Meta |

## أمان

- لا تشارك المفاتيح ولا تضعها في الكود أو في مستودع عام. إن تسرّب مفتاح فأعد توليده فوراً.
- كل الأسعار والمجاميع يحسبها ووكومرس، والخادم لا يقبل سعراً من النموذج. وإنشاء الطلب يُرفض إن لم يؤكد العميل صراحة.
- أنير يحدّ العميل بـ 40 رسالة في الساعة (قابل للتعديل بـ `MAX_MSGS_PER_HOUR`) لحماية رصيدك.
- أنير مساعد معلومات وليس بديلاً عن الطبيب أو الصيدلي، وقد ضُبط ليحوّل الحالات الطبية، لكن راجع محادثاته الأولى بنفسك وعدّل `anir-prompt.md` عند الحاجة.
